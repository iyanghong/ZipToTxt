源码和包内代码检查使用以下入口；读取产物的 Python 主、次版本须与构建版本一致：

```sh
python test_gui_controls.py
python test_git_archive.py --gui
python test_zip_to_txt.py
python packaging/test_bundle.py "可执行文件路径" test_gui_controls.py test_git_archive.py test_zip_to_txt.py
```

Windows 环境没有 Git，因此包内测试只运行 `test_gui_controls.py` 和 `test_zip_to_txt.py`。实际 EXE 使用 `wine start /unix .../ZipToTxt.exe` 独立启动，再运行 `packaging/test_frozen_windows.py` 检查主窗口和启动错误；启动检查等待窗口出现，不依赖固定的 8 秒延迟。

包内代码测试由归档读取器加载最终可执行文件中的 GUI、归档及 Git 模块，其他测试依赖由测试环境提供。实际冻结程序也分别启动，避免只验证源码而漏检启动器或附带运行库。

## 已验证的交互

- 分支关键字不区分大小写，覆盖本地及远程候选；无匹配时明确提示。过滤候选不改变当前分支和已选提交，实际更换分支才清空选择。
- 日期快捷项验证当天、昨天、最近 7 天、整月及不限，覆盖跨年、闰年二月和普通二月。真实快捷按钮填写两个日期并应用查询，隐藏选择仍保留；无效手输日期禁用确认，修正后恢复。
- 点击日期输入框弹出真实日历，点击日历按钮、日切换按钮和日期按钮均有效；支持跨年翻月、日期边界及手动输入。日历打开时保持输入框焦点，真实键盘事件能输入完整日期；查询期间关闭并禁用日期弹层。
- 逐行勾选通过真实表格鼠标事件验证，空格可以取消。全选和反选覆盖全部筛选结果，保留筛选范围外选择；清空全部清除隐藏选择。
- 真实临时仓库生成 205 次修改提交，首屏显示 200 条，全选确实选中 205 条并提示列表外 5 条；反选及加载更多后的状态正确。
- 未填写密码时，确认提交即可预览去重文件。预览展示实际路径、未压缩大小、文件数量和缺失项；返回修改保留勾选，确认后再次打开提交窗口回填之前的选择。
- 全部文件缺失时显示缺失清单，清单确认按钮禁用，不能生成空包。主界面开始压缩时再次生成最终清单；提前预览后修改磁盘内容，最终大小和实际归档均使用新的内容。
- 保留慢查询期间 Tk 定时回调响应、无 Git 时普通压缩、子目录范围、日期与作者筛选、合并、重命名、删除、符号链接和名称冲突，以及实际加密还原的既有检查。

## 本次修正

独立的日期键盘检查发现，普通日历顶层窗口会抢走输入框焦点。改为不带窗口装饰的日期弹层后，在最终三平台包内代码中重新验证：日历可见时，焦点仍在日期输入框，键盘事件能直接修改日期；日历提供关闭按钮，输入框支持 Esc 关闭。

Windows 第一次固定等待 8 秒的检查未发现主窗口。改用干净的 Wine 环境、独立桌面启动，并等待窗口出现后，最终 EXE 的主窗口检查及控件回归通过。未将 Wine 环境调整写入应用实现。

## 压缩包与校验

三份最终压缩包均实际解包，解包后可执行文件的 SHA-256 与原始产物一致。Windows ZIP 的 CRC 通过；Linux 执行权限保留；macOS 解包后的 `.app` 通过 `codesign --verify --deep --strict` 临时签名验证。`SHA256SUMS` 包含三个压缩包与独立 Windows EXE，并重新核对。

文件类型分别为 Windows PE32+ GUI x86-64、macOS Mach-O arm64、Linux ELF x86-64。`release/` 保持 Git 忽略。
