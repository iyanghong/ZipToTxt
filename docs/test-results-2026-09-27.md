# 2026-09-27 实测记录

## 测试数据与判定方式

输入目录包含 40 MiB 随机二进制文件、中文名称的文本文件和空目录。随机文件原始 SHA-256 为 `46104cbf634275a911d69f668f66b922a6b84b0bc48d977c3eb5297c55fcd5d0`。还原后逐字节比较文件，并检查目录结构。另用错误密码测试失败路径，检查未留下 `restored` 目录。

## 原版端到端测试

本节的 40 MiB 测试针对增加“指定输出位置”之前的版本。

| 对象 | 实际运行环境 | 结果 |
| --- | --- | --- |
| macOS 源码 GUI | macOS 26.5.2，Apple 芯片，Python 3.14/Tk | 调用界面处理回调并驱动 Tk 事件循环，压缩、错误密码、解压均通过；处理期间窗口持续响应。产生 2 个 TXT，大小分别为 50,000,000 和 5,941,908 字节；文件哈希、中文文本和空目录一致。 |
| macOS 发布包 `.app` | 同上 | 可启动，`codesign --verify --deep` 通过。当前机器未授予界面自动化权限，未对打包版完成按钮操作测试。 |
| Linux x64 发布包 | Ubuntu 22.04 容器，Xvfb 图形环境，x64 模拟运行 | 对发布包中的可执行文件实际点击操作；压缩、错误密码、解压均通过。产生 2 个 TXT，大小分别为 50,000,000 和 5,941,908 字节；文件哈希、中文文本和空目录一致。显示中文需要系统安装中文字体。 |
| 跨平台分片 | Linux 发布包生成，macOS 源码解密 | 还原成功，随机文件 SHA-256 与原件一致。 |
| 数字菜单 CLI | macOS 终端 | 通过伪终端实际输入 `1`、`2` 和密码，完成单文件压缩与还原；还原内容逐字节一致。 |
| Windows x64 发布包 | Wine 6 和 Wine 9，均非原生 Windows | 未通过 Wine 启动测试。Wine 6 在 PyInstaller 单文件父进程校验处报错；Wine 9 能解包，但内置 Python 初始化失败。带日志的诊断包在 Wine 9 中显示 `init_sys_streams: can't initialize sys standard streams`、`[WinError 6] Invalid handle`。不能从 Wine 失败推断原生 Windows 上的结果。 |
| 源码自检 | macOS Python | `python test_zip_to_txt.py` 通过，覆盖多分片、错误密码、额外 TXT、损坏分片、缺片和单文件还原。 |

## 指定输出位置更新后的复测

| 对象 | 结果 |
| --- | --- |
| 源码自检 | 默认路径和指定输出位置均通过；确认目标目录已存在时拒绝覆盖、错误密码后不留下还原目录。 |
| macOS 源码 GUI | 在 Tk 事件循环中使用目录选择回调，分别指定压缩和解压的输出位置；往返内容一致。 |
| 数字菜单 CLI | 用伪终端输入菜单数字与密码，两次分别使用 `--output-dir`；还原内容逐字节一致。 |
| Linux x64 新发布包 | 在 Xvfb 中实际操作 GUI，指定两个不同的输出位置，完成压缩、解压与逐字节比较。 |
| macOS 新发布包 | `.app` 可启动并通过 `codesign --verify --deep --strict`；按钮流程仍未在打包版验证。 |
| Windows x64 新发布包 | 已重新构建并检查压缩包；仍缺少原生 Windows x64 运行测试。 |

三个新发布压缩包均通过 `shasum -a 256 -c SHA256SUMS` 校验；解包后的程序与构建产物一致。Windows 发布包仍需在原生 Windows x64 上完成压缩、错误密码和解压的端到端测试，才能标为通过。
