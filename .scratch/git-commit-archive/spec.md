# 按 Git 提交打包变更文件

Status: ready-for-human

讨论日期：2026-10-07。用户已授权按建议实施，源码改造、本地验证和三个平台打包已完成。

## 已提出的功能

压缩时，输入路径为目录且处于 Git 仓库中，提供一个按提交打包的选项。提交列表支持多选，并可按日期、分支、用户筛选；归档包含所选提交变更的文件。

## 已核对的现有行为

现有压缩入口读取磁盘上的整个文件或目录，目录压缩不排除 `.git`、未跟踪文件或被忽略文件。GUI 和 CLI 调用相同的归档函数，保留输入目录的顶层名称，拒绝符号链接；还原到新目录，不覆盖已有内容。

当前发布程序附带 Python、Tkinter 和加密依赖，没有附带 Git。仓库检测必须区分 Git 命令是否可用与输入目录是否处于 Git 工作树；选择仓库子目录也可能检测到其上级仓库。

## 已确认的规则

所选提交用于生成文件路径清单，多个提交涉及相同路径时去重。归档读取这些路径在当前磁盘上的内容，不按提交分别保留历史版本；尚未提交的本地修改也会进入归档。

提交列表和归档文件范围均限定在所选目录及其子目录。选择仓库子目录时，不扩大到仓库其他位置。

Git 功能使用系统已安装的 Git，发行包不附带 Git。系统中找不到 Git 时禁用提交打包功能，保留原有文件和目录压缩功能。

当前不存在的路径在预览中列明并跳过；全部文件不存在或没有相关变更时停止，不生成空包。打包前展示最终文件清单，由使用者确认开始。

日期按提交时间筛选，采用本机时区，起止日期包含全天。作者按姓名或邮箱进行不区分大小写的包含匹配。

一次筛选一个分支，默认当前分支，包含本地分支和本机已有的远程跟踪分支；只读本地历史，不自动联网拉取。切换筛选分支时清空选择；改变日期或作者筛选时保留隐藏的已选提交，并持续显示已选数量。

目录压缩默认仍为完整目录，显式选择提交后启用提交变更文件包，可恢复普通模式。

## 实现约定

初始提交与空树比较，合并提交与第一父提交比较；重命名作为旧、新两条变更路径。路径去重后，只打包其中当前存在的普通文件。归档保留所选目录的顶层名称，不携带接收方删除指令。

符号链接、子模块目录、特殊文件和跨平台名称冲突拒绝打包；预览后文件消失或无法读取时终止，清理未完成输出。Git 查询在后台线程运行，提交列表每次显示 200 条，可继续加载。

本次增加 GUI 提交选择流程和共享归档的文件清单入口，CLI 保留原有完整归档。原有加密文本分片格式不变。当前源码和三个平台本地产物已更新，新包位于 `release/v0.2.0/`；尚未上传 GitHub Releases，原有 v0.1.0 发布包不变。

## 验证

临时 Git 仓库的目录范围、路径去重、当前内容、日期和作者筛选、合并与缺失路径检查通过；真实 Tk 控件与事件循环验证了筛选保留选择、切换分支清空选择、预览取消和确认、205 条历史分页、慢查询期间响应，以及无 Git 时普通压缩。详见 `docs/test-results-2026-10-07.md`。

三平台实际可执行文件启动、包内应用代码、压缩包解包与 SHA-256 核对均已检查。macOS 和 Linux 覆盖完整 Git/Tk 流程；Windows 在 Wine 9 覆盖主窗口、归档回归和无 Git 时普通 GUI 压缩还原，未做原生 Windows 验收。
