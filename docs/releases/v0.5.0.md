# ZipToTxt v0.5.0

## 主要改动

- 新增侧栏“粘贴文本还原”。每个输入项粘贴一份完整 TXT，可动态增加、替换或删除；支持按钮及 Ctrl+V／⌘V。
- 允许乱序粘贴，按内部片号自动排序，提示缺片、重复或混入其他归档。粘贴入口移除 ASCII 空格、制表符和 CR／LF，再严格校验；去除空白后每片最多 200 MB。
- 界面只显示片号、大小、状态和短预览。读取剪贴板、校验、解密和解压由后台进程执行，完整加密分片暂存到私有临时目录。进程启动本身也移至后台，修复 Windows／Wine 测试中发现的启动卡顿。
- 收齐分片后，选择输出目录并输入密码，在其中新建 `restored`，不覆盖已有目录。成功后清空分片，失败时保留以便重试；切换页面保留，关闭程序清理。文本和密码不会写入设置文件。
- 保留普通压缩／目录还原、各阶段真实字节进度、可配置分片大小、Git 提交筛选与文件预览，以及密码显隐和结果路径操作。

## 下载

| 文件 | 平台与用法 |
| --- | --- |
| `zip-to-txt-windows-x86_64.zip` | Windows x64，解压后双击 `ZipToTxt.exe` |
| `ZipToTxt.exe` | 同一个 Windows 程序，可直接下载运行 |
| `zip-to-txt-macos-arm64.zip` | macOS Apple 芯片，解压后打开 `ZipToTxt.app` |
| `zip-to-txt-linux-x86_64.tar.gz` | Linux x64，解压后运行 `./zip-to-txt-gui` |
| `SHA256SUMS` | 上述四个下载文件的 SHA-256 校验值 |

目标机器无需安装 Python。Git 提交选择使用系统 Git；没有 Git 时该功能禁用，其他归档操作仍可使用。

Linux 版在 Ubuntu 22.04（glibc 2.35）构建，需要兼容的图形桌面与系统库。macOS 版仅支持 arm64，并采用临时签名；Windows 程序未签名。系统首次打开时可能要求手动允许运行。

## 已完成验证

三个环境各使用真实系统剪贴板连续乱序粘贴 **120 MB、120 MB、106.77 MB** 三片，合计 **346.77 MB**；还原文件与原文件的 SHA-256 一致。

| 测试环境 | 所有阶段的最大界面回调间隔 |
| --- | --- |
| 原生 macOS arm64 | 30.1 ms |
| Windows x86_64／Wine 9 | 118.4 ms |
| Linux x86_64／Docker、Xvfb | 42.8 ms |

按 20 ms 定时回调测量，覆盖粘贴、错误密码重试及解密解压，均通过本环境 250 ms 的验收上限。测量结果不是对所有机器响应时间的保证。

测试读取最终产物内代码并核对源码一致性，后台进程实际启动对应发布程序；还覆盖真实控件、替换失败与重试、重复片、清理和既有功能回归。三个发布包均通过 CRC 或解包检查、程序 SHA-256 与执行权限检查，macOS 临时签名验证通过。

Windows 使用 Wine，Linux 使用 Docker 和 Xvfb；尚未在原生 Windows 或真实 Linux 桌面完成人工验收。Windows 环境没有系统 Git，其 Git 窗口测试使用固定提交数据；真实 Git 集成在 macOS 和 Linux 验证。详细结果见[大文本测试记录](https://github.com/iyanghong/ZipToTxt/blob/v0.5.0/docs/test-results-paste-2026-10-10.md)。

本次沿用既有加密容器与核心归档格式，新增粘贴入口复用原有还原校验和输出保护。超过 50 MB 的分片仍须使用支持该大小的版本还原；本次未重新执行旧版九组跨平台互通矩阵。
