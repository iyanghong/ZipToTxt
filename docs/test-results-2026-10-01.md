# 2026-10-01 分片上限配置实测

压缩时可设置 1～200 MB 的整数上限，默认 50 MB；还原时自动接受这个范围内的分片，归档格式未改变。MB 按 1,000,000 字节计算。

| 对象 | 结果 |
| --- | --- |
| 源码自检 | `python3 test_zip_to_txt.py` 通过。40 MiB 随机文件按默认值产生 2 片，第一片恰为 50,000,000 字节；改为 100 MB 时产生 1 片，大于 50 MB 且不超过 100 MB。两种配置均还原成功，SHA-256 一致。1 MB 多片、末尾 NUL、错误密码、重复分片、指定输出位置也通过；0、201、1.5 和布尔值被拒绝。 |
| 数字菜单 CLI | 实际输入菜单数字及测试密码，使用 `--part-size-mb 1` 压缩 1.7 MB 随机文件，最大分片恰为 1,000,000 字节；再用 CLI 还原，SHA-256 一致。 |
| macOS 打包版 GUI | 实际在窗口输入 1 MB 上限并压缩 2.3 MB 随机文件，产生 4 片，大小为 1,000,000、1,000,000、1,000,000 和 68,048 字节。随后在重新构建的 `.app` 中解密 Linux 生成的 55,941,344 字节分片，完成弹窗显示指定输出目录，文件 SHA-256 与原件一致。 |
| Linux x64 打包代码到 macOS | 从 Linux 可执行文件内加载实际打包的归档模块，以 100 MB 上限压缩 40 MiB 随机文件，得到 55,941,344 字节的单片。macOS 源码和打包版 GUI 均成功还原，SHA-256 一致。本轮未操作 Linux GUI 窗口。 |
| Windows x64 | 已重新构建 GUI `.exe`，检查为 x64 PE 程序。没有原生 Windows 测试环境，尚未验证新版窗口操作和端到端还原。 |

三个发布压缩包均已解包核对，程序与本次构建产物逐字节一致，`shasum -a 256 -c SHA256SUMS` 全部通过；解包后的 macOS `.app` 通过 `codesign --verify --deep --strict`。
