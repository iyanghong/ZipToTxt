# 大文本粘贴使用独立进程和文件暂存

多个文本分片各自可能达到 100～200 MB。粘贴还原将剪贴板读取、Base64 校验与解密解压放入独立 spawn 进程，GUI 只接收短摘要和进度，完整加密分片存入私有临时目录；每次只读取或还原一项任务，避免多片全文在界面进程中累积。这个入口在完成或关闭时清理临时数据，失败时保留已导入分片供重试；原归档格式和输出保护由现有还原函数执行。

选择进程需要承担启动成本及三平台冻结程序的 spawn 验证，但可将剪贴板调用及整片解码的耗时与界面事件循环分开。冻结入口调用 `multiprocessing.freeze_support()`，工作进程启动测试使用最终可执行文件；此要求参考 [PyInstaller 文档](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#multi-processing)。这补充了 ADR 0002 中对原有线程任务的约定。

2026-10-10 的 Windows／Wine 大文本测试发现，直接在界面回调中启动冻结工作进程仍可能阻塞约 0.75 秒。因此，`Process.start()` 本身也由后台线程调用；界面轮询启动结果及短消息，不等待进程创建或结束。修正后同一测试中的最大界面回调间隔降至约 118 ms。测试和测量范围见[测试记录](../test-results-paste-2026-10-10.md)。
