# ZipToTxt v0.4.1

## 主要改动

- Git 提交与打包文件清单改为上下排列，筛选区占满窗口宽度，可拖动分隔线调整两张表的高度。双击行或按 Enter 可查看、复制完整提交信息或文件路径。
- 新增“近 1 天”“近 2 天”，分别按最近 24／48 小时筛选；保留当天、昨天、最近 7 天、本月及手动日期和日历。
- 支持分支关键字、用户筛选、提交多选和自动文件预览。所选提交的变更路径合并去重，只包含选择的目录及子目录；内容读取打包时的当前磁盘版本。
- 主界面采用浅色侧栏，显示各阶段真实字节进度，提供密码显隐、复制输出路径，以及目录和分片大小记忆。密码不会保存。
- 压缩和还原均可指定输出位置；TXT 分片大小默认 50 MB，可配置为 1～200 MB，输出不覆盖已有目录。

## 下载

| 文件 | 平台与用法 |
| --- | --- |
| `zip-to-txt-windows-x86_64.zip` | Windows x64，解压后双击 `ZipToTxt.exe` |
| `ZipToTxt.exe` | 同一个 Windows 程序，可直接下载运行 |
| `zip-to-txt-macos-arm64.zip` | macOS Apple 芯片，解压后打开 `ZipToTxt.app` |
| `zip-to-txt-linux-x86_64.tar.gz` | Linux x64，解压后运行 `./zip-to-txt-gui` |
| `SHA256SUMS` | 上述四个下载文件的 SHA-256 校验值 |

目标机器无需安装 Python。Git 提交选择使用系统 Git；没有 Git 时该功能禁用，普通压缩和还原仍可使用。

Linux 版在 Ubuntu 22.04（glibc 2.35）构建，需要兼容的图形桌面与系统库。macOS 版仅支持 arm64，并采用临时签名；Windows 程序未签名。系统首次打开时可能要求手动允许运行。

## 已完成验证

三个平台均验证了包内应用代码与源码一致、归档往返及错误处理、实际 Tk 控件、冻结程序启动，以及与 v0.3.0 的双向还原；发布压缩包还通过解包和 SHA-256 校验。macOS、Linux 已执行真实 Git 集成测试。

Windows 构建和运行检查使用 Wine 9；Linux 使用 Docker 和 Xvfb。Windows 测试环境没有系统 Git，其布局测试使用固定提交数据。尚未在原生 Windows 或真实 Linux 桌面做人工点击验收；macOS 已完成真实 Tk 和 `.app` 启动检查。详细结果见[测试记录](https://github.com/iyanghong/ZipToTxt/blob/v0.4.1/docs/test-results-git-layout-2026-10-08.md)。

本次沿用既有加密容器和核心归档格式。各平台分别通过旧版双向还原；跨平台九组互通结果来自 v0.4.0，本次未重新执行该矩阵。
