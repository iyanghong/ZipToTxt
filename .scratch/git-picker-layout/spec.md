# Git 提交窗口：上下列表和最近时间筛选

Status: ready-for-human

讨论日期：2026-10-08。用户反馈 Windows 的左右分栏挤压提交信息及文件路径，要求上下两栏，并增加近 1 天、近 2 天。

## 实施范围

- 筛选区占满窗口宽度；提交列表在上，文件清单在下，分隔线可拖动。
- 提交时间、用户姓名及邮箱继续保留；时间列按字体测量宽度。双击提交或文件可查看、选择和复制完整信息。
- 近 1 天、近 2 天按用户确认的最近 24／48 小时解释，以每次查询时刻计算，使用提交时间。保留当天等自然日筛选、手动日期和日历。
- 选择最近时间后，继续按分支及用户筛选时保留最近时间模式；输入日期或选择其他日期快捷项切回自然日模式。重新打开窗口回填已确认的筛选和提交。
- 保留自动文件预览、去重、缺失提示、当前磁盘内容及输出不覆盖规则。
- 用真实 Git 长路径、长作者和长说明复现问题，并验证小窗口、全文查看和时间边界。重新构建三个平台本地产物，不自动上传 GitHub。

## 验收

- 上下列表各占窗口有效宽度；默认及 980×600 窗口均能显示完整数据行。
- 长信息可以查看全文，不因表格截断丢失访问入口。
- 最近 24／48 小时不等同于当天；覆盖窗口起点、刚好越界、查询时刻及未来时间。
- 三个平台产物代码与当前源码一致；执行包内回归、启动及归档解包校验，并说明 Wine／Xvfb 测试边界。
